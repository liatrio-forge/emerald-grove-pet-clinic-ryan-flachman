# Questions: Health Timeline CSS (13) — Round 1

## Resolved

| # | Question | Resolution |
|---|----------|------------|
| Q-1 | **Source file** — edit `petclinic.scss` or `petclinic.css` directly? | Edit `petclinic.scss`. `petclinic.css` is auto-generated by `./mvnw package -P css` and would be overwritten on the next compile. |
| Q-2 | **Color values** — what hex values for green / amber / red on the dark `#1a1f23` background? | Green → `$spring-green` (`#24AE1D`, already a SCSS variable); Amber → Bootstrap `$warning` / `#ffc107`; Red → Bootstrap `$danger` / `#dc3545`. Text on green/amber → dark (`#111111`); text on red → white (`#f8f9fa`). |
| Q-3 | **Spinner implementation** — reuse Bootstrap `.spinner-border` or define a custom `@keyframes`? | Define a custom `@keyframes ai-spinner-rotate` for the rotation and apply it in `.ai-spinner`. The existing `.myspinner` in `petclinic.scss` uses `animation-name: spinner` without a visible `@keyframes` block; use a distinct name to avoid any collision. |
| Q-4 | **Badge shape** — fully custom or Bootstrap `.badge` override? | Fully custom pill classes that do not depend on Bootstrap `.badge` markup. Each urgency class can stand alone on a `<span>`. |
| Q-5 | **`.health-tag` visual** — filled or outlined pill? | Outlined pill with `$spring-green` border and text on transparent background, consistent with the dark theme. |
| Q-6 | **CSS compile gate for E2E** — does the E2E runner need a pre-compile step? | Yes. The Playwright suite starts the Spring Boot app but does not recompile SCSS. After modifying `petclinic.scss`, run `./mvnw package -P css` once to regenerate `petclinic.css`. The validation plan documents this gate. |

## Open

None — all blocking questions are resolved.
